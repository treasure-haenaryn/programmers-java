# 리코쳇 로봇 — 코드 리뷰

- 문제: https://school.programmers.co.kr/learn/courses/30/lessons/169199 (Lv2, 연습문제)
- 리뷰 날짜: 2026-10-08
- 리뷰 시점 결과: 예제 실행 시 무한 루프 (끝나지 않음)

## 잘한 점

- 이동 횟수를 `Node.count`로 칸마다 들고 다님 (큐에서 꺼낸 개수 ≠ 이동 횟수)
- 미끄러지는 도중에는 visited를 보지 않음 (지나가는 칸은 상태가 아님)
- G는 지나갈 때가 아니라 멈춘 칸에서 확인
- D에 부딪히면 한 칸 되돌려서 멈춘 칸을 구함
- 필드 `N`, `M`에 `int` 없이 대입 (이전의 지역 변수 가림 문제 해결)

## 버그 1. 이미 방문한 칸도 다시 큐에 넣음 → 무한 루프

```java
visited[nr][nc] = true;
queue.offer(new Node(nr, nc, count + 1));
```

visited를 표시만 하고 확인하지 않는다. 같은 칸이 계속 큐에 들어가서, 답이 없는 예제 #2에서는 큐가 영원히 비지 않는다.
제자리에 멈추는 경우(바로 옆이 벽/D)도 자기 자신을 다시 넣는다.

**수정**:

```java
if (visited[nr][nc]) continue;
visited[nr][nc] = true;
queue.offer(new Node(nr, nc, count + 1));
```

## 버그 2. 첫 칸을 건너뛰고 미끄러지기 시작

```java
int nr = r + dr[i];      // 이미 한 칸 이동한 위치에서 시작
...
while (true) {
    nr += dr[i];         // 검사 전에 또 한 칸 → 바로 옆 칸은 검사 안 함
```

바로 옆 칸이 D여도 검사하지 않고 넘어가서, 장애물을 뚫고 지나간다.

- 버그 1만 고친 결과: 예제 #1이 `7` 대신 `4`, 랜덤 3,000개 중 1,200개 불일치
- 반례: `["...D..", "....DD", "G.D...", "......", ".D...R"]` → 정답 -1, 결과 3

**수정**: 현재 칸에서 시작

```java
int nr = r;
int nc = c;
```

## 검증

- 두 군데 수정 후 예제 2개 PASS
- 랜덤 보드 3,000개를 별도 BFS 구현과 비교: 모두 일치

## 다듬을 만한 부분

벽 밖으로 나갔을 때도 D와 똑같이 "한 칸 되돌리기"로 처리하면 범위 보정 if문 4개가 필요 없다.

```java
while (true) {
    int tr = nr + dr[i], tc = nc + dc[i];
    if (tr < 0 || tr >= N || tc < 0 || tc >= M || map[tr][tc] == 'D') break;
    nr = tr;
    nc = tc;
}
```

다음 칸을 먼저 보고, 갈 수 있을 때만 이동 → 멈춘 칸 = 마지막으로 이동한 칸.

## 기억할 포인트

- BFS의 visited는 표시만 하면 안 되고, 큐에 넣기 전에 확인까지 해야 한다
- 상태 = 멈춘 칸. visited와 도착 판정은 멈춘 칸 기준, 미끄러지는 도중의 칸은 무시
- "한 칸 앞을 먼저 보고 갈 수 있으면 이동" 패턴이 "이동 후 되돌리기"보다 경계 실수가 적다
