# 숫자의 표현 — 코드 리뷰

- 문제: https://school.programmers.co.kr/learn/courses/30/lessons/12924 (Lv2, 연습문제)
- 리뷰 날짜: 2026-10-07
- 리뷰 시점 결과: 예제 FAIL (`expected=4, actual=2`) → 이후 수정 완료

## 잘한 점

- 연속된 자연수 → 모두 양수 → 합으로 포인터 이동 방향을 정하는 투 포인터 접근
- `while (sum > n)`으로 왼쪽을 계속 줄이는 가변 윈도우 구조
- 관리할 상태(왼쪽 인덱스, 오른쪽 인덱스, 합, 개수)를 주석으로 먼저 정리

## 버그. `sum` 초기값이 1

```java
int sum = 1;
int left = 1;
for (int right = 1; right <= n; right++) {
    sum += right;    // right = 1일 때 1을 또 더함
```

창은 `[1]`인데 `sum`은 2가 된다. 남는 1은 `left`를 옮길 때도 빠지지 않아서, `sum`은 항상 **실제 구간 합 + 1**이다.
결국 "합이 n인 구간"이 아니라 "합이 n-1인 구간"을 세게 된다.

```
n = 15 → 실제로는 합이 14인 구간을 셈
  2 + 3 + 4 + 5 = 14
  14            = 14
→ 2개 (실행 결과 actual=2와 일치)
```

**수정**: `int sum = 0;`

검증: 예제 PASS, n = 1 ~ 10,000 전부 완전탐색과 비교해 일치

## 기억할 포인트

- 투 포인터의 `sum`은 "지금 창 `[left, right]` 안 값들의 합"이라는 약속. 시작 시점부터 맞는지 확인한다.
  - 루프가 첫 원소를 직접 더함 → `sum = 0`에서 시작
  - 루프 전에 첫 원소를 미리 넣음 → `sum = 첫 원소`, 루프는 다음 원소부터
- 초기값·경계값에서 하나 차이로 틀리는 실수가 반복됨 → 루프 첫 반복과 마지막 반복에 값을 직접 대입해 보기
