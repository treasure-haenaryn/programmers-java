# 배달 — 코드 리뷰

- 문제: https://school.programmers.co.kr/learn/courses/30/lessons/12978 (Lv2, 다익스트라)
- 리뷰 날짜: 2026-10-08
- 리뷰 시점 결과: 예제 2개 모두 FAIL (`actual=1`)

## 잘한 점

- 다익스트라 구조: `dist` 배열, 최소 힙(`PriorityQueue`), 오래된 후보 건너뛰기(`nowDistance != dist[now]`)
- 양방향 그래프로 간선 저장
- `nextDistance <= k` 가지치기: K를 넘는 경로는 큐에 넣지 않음 (정답에 영향 없음)
- 같은 두 마을 사이 여러 도로: 인접 리스트에 모두 넣으면 다익스트라가 알아서 짧은 것을 고름

## 버그 1. 시작점이 0번

```java
return dijkstra(0);
```

마을은 1번부터이고 음식점은 1번 마을에 있다. 0번은 비워 둔 칸이라 간선이 없어서, 시작하자마자 끝나고 `count = 1`을 반환한다.

**수정**: `dijkstra(1)`

## 버그 2. 거리 갱신할 때마다 `count++`

1번만 고쳐도 예제는 PASS가 나오지만 채점에서는 틀린다.
다익스트라에서는 같은 마을의 거리가 여러 번 갱신될 수 있어서, 같은 마을을 두 번 이상 센다.

반례 (K = 5):

```
도로: 1-2 (5), 1-3 (1), 3-2 (1)

1에서 시작 (count = 1)
  → 2번 거리 5로 갱신          count = 2
  → 3번 거리 1로 갱신          count = 3
3번 꺼냄
  → 2번 거리 1+1 = 2로 다시 갱신 count = 4   ← 2번을 또 셈

정답: 1, 2, 3 → 3개
```

**수정**: 탐색 중에는 세지 말고, 다익스트라가 끝난 뒤 `dist` 배열 기준으로 센다.

```java
// while 루프 안의 count++ 는 지우고, 끝난 후에
int count = 0;
for (int i = 1; i <= vertexCount; i++) {
    if (dist[i] <= k) count++;
}
return count;
```

`dist[1] = 0`이므로 1번 마을도 자연스럽게 포함된다.

## 검증

- 두 군데를 고친 버전: 예제 2개 PASS
- 랜덤 입력 3,000개를 플로이드-워셜(단순 최단거리) 결과와 비교: 모두 일치

## 기억할 포인트

- 다익스트라에서 **갱신 횟수 ≠ 도달한 노드 수**. "몇 개인지"는 탐색이 끝난 뒤 `dist` 배열로 센다.
- 세는 대상이 정확히 무엇인지 다시 확인하기 (전력망 나누기의 "크기 vs 차이"와 같은 종류의 실수)
- 노드 번호가 1부터인 문제에서 시작점·배열 범위가 0부터로 섞이지 않았는지 확인
