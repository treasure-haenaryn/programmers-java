# 연속 부분 수열 합의 개수 — 코드 리뷰

- 문제: https://school.programmers.co.kr/learn/courses/30/lessons/131701 (Lv2, 연습문제)
- 리뷰 날짜: 2026-10-07
- 리뷰 시점 결과: 예제 FAIL (`expected=18, actual=14`) → 이후 수정 완료

## 잘한 점

- 원형 수열을 배열 두 번 이어 붙이기로 처리
- 길이 n(전체 합)은 `total`로 따로 처리
- 길이별 슬라이딩 윈도우 + `Set`으로 중복 제거

## 버그. 길이 n-1이 빠짐

```java
for (int k = 1; k < elements.length - 1; k++)   // k = 1 ~ n-2
```

길이 n은 `total`로 넣었으니 길이 n-1이 통째로 빠진다.
예제에서 길이 4로만 만들어지는 합 `[13, 15, 18, 21]` 4개가 빠져서 18 → 14.

**수정**:

```java
for (int k = 1; k < elements.length; k++)       // k = 1 ~ n-1
```

검증: 예제 PASS, 랜덤 입력 5천 개를 완전탐색과 비교해 모두 일치

## 다듬을 만한 부분

### `set.add(sum)` 위치

창 크기가 k에 도달하기 전의 합도 들어간다. 실제로 존재하는 부분 수열 합이라 답은 맞지만 의도("길이 k짜리만")와 다르다.

```java
sum += circle[right];
if (right - left + 1 == k) {
    set.add(sum);              // 창 크기가 정확히 k일 때만
    sum -= circle[left++];
}
```

### `right`가 `2n` 끝까지 감

시작 위치가 n 이상인 창은 앞에서 본 구간과 같다. `right < n + k - 1`까지만 돌면 충분 (지금도 Set이 걸러 줘서 답은 맞음).

## 핵심 아이디어: 원형 배열 다루기

- 방법 A: `elements[(i + j) % n]`
- 방법 B: 배열을 2배로 이어 붙이기 → 원형 구간이 일반 구간처럼 보임

| 범위 | 조건 | 어기면 |
|---|---|---|
| 시작 위치 | `0 ~ n-1` | 같은 구간을 다시 셈 (답은 맞지만 낭비) |
| 길이 | `1 ~ n` | 같은 원소를 두 번 더함 (틀린 합) |

## 기억할 포인트

- `<` / `<=` 쓸 때 마지막으로 도는 값을 직접 대입해 확인 (`k < n-1`이면 n-1이 빠짐)
- 서로 다른 구간의 합이 같은 건 정상 → Set이 처리
