# 두 큐 합 같게 만들기 — 코드 리뷰

- 문제: https://school.programmers.co.kr/learn/courses/30/lessons/118667 (Lv2, 2022 KAKAO TECH INTERNSHIP)
- 리뷰 날짜: 2026-10-06
- 리뷰 시점 결과: 예제 3개 모두 PASS (`Solution.java`, Deque 풀이)
- 추가 풀이: `SolutionTwoPointer.java` (하나의 배열 + 투 포인터)

## 잘한 점

- `sum1`, `sum2`, `total`, `k`를 모두 `long`으로 선언 (원소 최대 10억 → 오버플로우 방지)
- 전체 합이 홀수이면 바로 -1 반환
- `sum1 > k`면 q1에서 빼고, 아니면 q2에서 가져오는 그리디 구조
- 작업 횟수 상한으로 성공/실패 두 가지 출구를 모두 둠

`poll()`이 빈 큐에서 호출될 일은 없다.

- q2가 비면 `sum1 = total > k` → q2에서 꺼내는 분기로 안 감
- q1이 비면 `sum1 = 0 < k` → q1에서 꺼내는 분기로 안 감

## 다듬을 만한 부분

- 루프에서는 `sum1`과 `k`만 비교하므로 `sum2` 갱신은 불필요
- 투 포인터 버전은 박싱이 없고 "경계만 움직인다"는 감각을 익히기 좋음

## 핵심 아이디어

### 1. 매 단계 선택지가 하나뿐 → 탐색이 아니라 시뮬레이션

- q1 → q2로 옮기면 `sum1` 감소, q2 → q1로 옮기면 `sum1` 증가
- `sum1 > target`이면 q1에서 빼는 것만 의미 있음, `sum1 < target`이면 q2에서 가져오는 것만 의미 있음

### 2. 두 큐 = 원형 배열 위의 경계 두 개

```
[3, 2, 7, 2 | 4, 6, 5, 1]   q1 = [start, end)
```

- q2에서 pop → q1에 insert: q1 끝과 q2 앞은 원래 붙어 있는 자리 → `end++`
- q1에서 pop → q2에 insert: 원형이라 q2 끝 다음이 q1 앞 → `start++`
- 원소는 옮기지 않고 경계만 이동, 포인터가 `2n`을 넘으면 `% 2n`으로 감쌈

### 3. 종료 조건 (-1 판단)

- 전체 합이 홀수 → -1
- **시작점(`start`)이 한 바퀴(`2n`)를 돌면 모든 연속 구간을 확인한 것** → 못 찾았으면 -1
- `4n`, `3n` 같은 상한은 이 추론을 숫자 하나로 뭉뚱그린 것. 매직 넘버 대신 "무엇을 다 보면 끝나는가"로 조건을 세운다.

```java
while (start < len) {          // len = 2n
    if (sum1 == k) return count;
    if (sum1 > k) { sum1 -= arr[start % len]; start++; }
    else          { sum1 += arr[end % len];   end++;   }
    count++;
}
return -1;
```

## 흔한 잘못된 풀이 (블로그 코드)

```java
while (left < right && right < totalQueue.length) { ... }
```

- **문제 1**: `right++` 직후 합이 맞아도 루프 조건이 먼저 false가 되어 확인 없이 -1
  - 반례: `[6, 1]`, `[2, 3]` → 정답 3, 결과 -1
- **문제 2**: `right`가 끝에 닿아도 `left`는 더 움직일 수 있는데 멈춤, 원형 처리도 없음
  - 반례: `[5, 4, 2]`, `[1, 1, 5]` → 정답 5, 결과 -1
- **수정**: 종료 기준을 `left < 2n`으로, `right`는 `% 2n`으로 원형 처리
- BFS 완전탐색과 랜덤 입력 3만 개 비교: 원본 351개 불일치 → 수정본 0개

## 기억할 포인트

- 매 단계 행동이 하나로 정해지면 시뮬레이션
- 큐 두 개를 오가는 상태는 원형 배열 + 포인터 두 개로 단순화할 수 있다
- 종료 조건은 매직 넘버가 아니라 "무엇을 다 보면 끝나는가"
