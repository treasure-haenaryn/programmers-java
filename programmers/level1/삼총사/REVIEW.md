# 삼총사 — 코드 리뷰

- 문제: https://school.programmers.co.kr/learn/courses/30/lessons/131705 (Lv1, 연습문제)
- 리뷰 날짜: 2026-10-07
- 리뷰 시점 결과: 예제 3개 모두 FAIL (`actual = 1, 2, 3`) → 이후 수정 완료

## 잘한 점

- 재귀 조합 뼈대: 시작 인덱스 넘기기, `i + 1`로 다음 후보 고르기

## 버그 1. 첫 호출의 `depth`가 3

```java
combination(0, 3);
```

`depth`는 "지금까지 몇 명 골랐는가". 3으로 시작하면 아무것도 안 고른 상태에서 바로 종료 조건에 걸려 `answer++`.

**수정**: `combination(0, 0);`

## 버그 2. 합이 0인지 확인하지 않음

3명을 고르면 무조건 `answer++` → "3명 조합의 개수"를 세는 셈.

**수정**:

```java
if (depth == 3) {
    if (selected[0] + selected[1] + selected[2] == 0) answer++;
    return;
}
```

## 버그 3. `answer`가 호출 사이에 초기화되지 않음

`answer`가 필드라서 같은 `sol` 객체로 테스트를 여러 번 돌리면 값이 쌓인다 (실행 결과 1, 2, 3).
`solution()` 시작 시 `answer = 0;`으로 초기화한다.

검증: 세 군데 수정 후 예제 3개 모두 PASS

## 덤: 더 간단한 방법

n ≤ 13이라 3중 for문(`i < j < k`)으로 충분 (13C3 = 286번).
고르는 개수가 작고 고정이면 for문, 개수가 입력에 따라 바뀌면(M개 고르기) 재귀 조합.

## 기억할 포인트

- 재귀의 시작 인자는 "아직 아무것도 안 한 상태"를 나타내야 한다
- 필드에 결과를 모으면 `solution()` 시작 시 초기화
